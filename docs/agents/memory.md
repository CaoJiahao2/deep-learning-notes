## 1 概述 {#1}

LLM 的上下文窗口是有限的——长对话、长工具结果、多轮交互都可能被截断。**记忆机制**让 Agent 突破上下文限制，跨会话保留关键信息、按需检索并使用。

记忆系统需要回答三个核心问题：

1. **写什么**：从对话中提取哪些事实/事件/技能写入长期记忆；
2. **何时写**：每轮都写、关键事件触发、还是会话结束批量摘要；
3. **如何用**：检索时返回什么形态（原文 / 摘要 / 实体）、如何注入 prompt。

这三个问题连起来就是记忆系统的**生命周期**主线：写入 → 检索 → 反思与巩固 → 遗忘（见 5.6 节）。记忆在 Agent 核心循环中的位置见 [AI Agent 基础与核心循环](./fundamentals.md)。

## 2 短期 vs 长期记忆 {#2}

### 2.1 短期记忆 (Short-term)

即当前对话的上下文窗口（in-context）。容量受 token 上限约束，随对话增长会被截断或溢出。

### 2.2 长期记忆 (Long-term)

跨会话持久化，通常以向量库/摘要形式存储，按需检索注入上下文。

```text
写入：把关键事实/对话摘要 → Embedding → 写入长期记忆库
检索：当前问题 → Embedding → 相似度检索 → 取回相关历史 → 注入 prompt
```

### 2.3 对比

| 维度 | 短期记忆 | 长期记忆 |
|------|----------|----------|
| 容量 | 受上下文窗口限制 | 理论上无限 |
| 延迟 | 零 | 检索延迟 |
| 持久性 | 会话结束即消失 | 跨会话保留 |
| 适用 | 当前任务细节 | 跨任务偏好/事实 |

### 2.4 认知科学视角：四类记忆

把 Agent 记忆与人类记忆类比，可以为系统设计提供"分类学"：

| 记忆类型 | 人类类比 | Agent 中的对应物 | 典型寿命 |
|---|---|---|---|
| 工作记忆 (working) | 前额叶维持数秒的活跃表征 | 上下文窗口 / MemGPT 的 working context | 单轮–单会话 |
| 情景记忆 (episodic) | 自传式事件（"上周三做了什么"） | 对话与工具调用日志、事件流（A-MEM 笔记、Mirix 事件层） | 跨会话 |
| 语义记忆 (semantic) | 事实与概念知识 | 实体-关系库、知识图谱（Mirix 知识层） | 长期，可更新 |
| 程序性记忆 (procedural) | 技能与习惯（骑自行车） | 工具调用经验、技能库/prompt 模板（Mirix 工具层） | 长期 |

两个有启发性的理论：**多存储模型**（Atkinson–Shiffrin，信息从工作记忆进入长期记忆需要复述与编码）对应"写入需要显式加工，而非全文照抄"；**互补学习系统**（CLS：海马快速学习、新皮层慢速巩固）对应"写入快、巩固慢"——Agent 应先落一条可追溯的情景记忆，再异步地把它合并、蒸馏成语义记忆。

## 3 记忆形态 {#3}

| 形态 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 向量记忆 | 原文/摘要向量化，语义检索 | 通用、自动 | 粒度细、易冗余 |
| 摘要记忆 | 对历史滚动摘要 | 节省 token | 细节丢失 |
| 实体记忆 | 以结构化方式记录实体属性与关系 | 可推理、可对齐 | 抽取成本高 |
| 事件记忆 | 按时间序记录发生过的事件 | 适合"发生过什么" | 长程易膨胀 |

实践中常混合使用：摘要 + 实体 + 关键事件三元组。存储后端的选择同样重要，下面展开。

### 3.1 向量数据库后端

把记忆条目 embedding 后存入 ANN 索引（HNSW 等），检索用相似度 top-k。

- 优点：通用、语义检索、生态成熟（FAISS、pgvector、各托管向量库）；
- 缺点：条目彼此独立，时间、因果、冲突等关系不可见；同义记忆容易冗余膨胀；
- 适合：对话片段、工具结果等非结构化内容的通用存储。

### 3.2 图数据库后端

把实体与关系抽取为三元组（带时间戳）存入图数据库，检索支持多跳推理。

- 优点：天然表达"谁-做了什么-对谁"，支持多跳查询与矛盾检测；
- 缺点：抽取与维护成本高，图质量依赖 LLM 抽取的一致性；
- 代表：GraphRAG 式知识层、Zep/Graphiti 的时序知识图谱。

### 3.3 KV Cache 扩展：长上下文即记忆

另一条路线不建外部库，把"记忆"直接理解为上下文与 KV Cache：

- **prompt caching / 会话续传**：把历史 KV 保留在服务端复用，等价于把工作记忆做大；
- **KV 压缩与卸载**：对长历史做 token 淘汰或量化，保住窗口内的注意力状态；
- 优点：零检索误差（信息不经过"写入-检索"的有损管道）、实现简单；
- 缺点：成本随长度线性增长、跨会话不天然持久、无法跨用户共享。

适合单会话超长文档理解（见 [长上下文与 RAG](../llm-mllm/long-context-rag.md)）；跨会话个性化仍需外部记忆。

### 3.4 文件 / 笔记式后端

把记忆写成人类可读的文件（markdown 笔记、目录结构），检索用关键词/文件遍历与 embedding 双轨。

- 优点：可审计、可人工编辑、与开发工具链兼容（很多编码 Agent 用 `MEMORY.md` 式约定）；
- 缺点：需要严格的格式约定，纯语义检索能力弱；
- 代表：A-MEM 的结构化笔记、Letta 的文件式记忆层。

### 3.5 记忆与 RAG 的关系

RAG 与 Agent 记忆共用同一套检索技术，但定位不同：

| | RAG | Agent 记忆 |
|---|---|---|
| 语料 | 外部静态文档（事先存在） | Agent 自己的交互历史（动态生成） |
| 写入方 | 人 / 外部系统 | Agent（或其记忆模块） |
| 关键操作 | 检索 | 写入、反思、巩固、遗忘、检索 |
| 典型问题 | 切分与索引质量 | 冗余、过时、冲突、隐私 |

可以粗略地说：**记忆是 Agent 自己写入并维护的 RAG**。两者常常组合：个性化偏好用记忆、领域知识用 RAG，见 [Agentic RAG](./agentic-rag.md) 与 [个性化技术综述](../llm-mllm/personalization.md)。

## 4 MemGPT：分页式记忆管理 {#4}

### 4.1 核心思想

**MemGPT** 借鉴操作系统的虚拟内存与分页机制：把 LLM 上下文窗口视为主存，外部向量库视为磁盘，由 LLM 自主决定何时把哪些内容"换入"主存或"换出"到磁盘，从而在有限窗口内管理超长上下文。

```text
+--------------------------------------------------+
|  Main Context (LLM 上下文窗口 / "主存")          |
|  ┌────────────┐ ┌────────────┐ ┌──────────────┐ |
|  | System     | | Working    | | Recalled     | |
|  | Prompt     | | Memory     | | (从磁盘换入) | |
|  └────────────┘ └────────────┘ └──────────────┘ |
+--------------------------------------------------+
                ▲  recall (page-in)
                ▼  archive  (page-out)
+--------------------------------------------------+
|  External Memory ("磁盘": 向量库 / 摘要库)        |
+--------------------------------------------------+
```

### 4.2 LLM 自主决策

MemGPT 的关键创新：让 LLM 自己输出控制指令（`recall` / `archive`），决定何时把外部记忆中的内容"换入"主上下文，何时把主上下文中的内容"换出"到外部存储。这相当于把"内存管理"内化为 LLM 的一个可调用工具。

### 4.3 演进：Letta

后续 Letta（MemGPT 团队的商业化产品）把"分页"做到对开发者透明的 API 层，并加入更丰富的记忆类型（标签、关系、事件）。

## 5 2025 新进展：笔记式与层级记忆 {#5}

### 5.1 A-Mem (NeurIPS 2025)

**A-Mem** 提出"笔记式记忆"：每条新对话产生一条结构化笔记（包含时间、主体、关键词、上下文摘要），Agent 可在笔记之间自动建立链接（如"派生"、"扩展"、"冲突"），形成可演化的记忆图。

### 5.2 Mirix

**Mirix** 把记忆分为多层：

- **核心记忆**：长期偏好、关键事实；
- **事件记忆**：时序化的事件流；
- **知识记忆**：实体与关系图；
- **工具记忆**：调用工具的经验；
- **反思记忆**：Agent 自己的内省与评估。

每层都有独立的检索与写入策略。

### 5.3 何时触发写入

- **每轮写入**：最简单但易冗余；
- **事件触发**：在检测到"偏好表达"、"事实陈述"、"技能演示"等模式时写入；
- **会话结束批量摘要**：成本低但细节丢失；
- **重要性打分**：让模型对每条信息打分，仅保留高重要性的。

### 5.4 记忆写入的"双向循环"

近期工作强调：

- **写入要可追溯**：每条记忆需有出处（哪轮对话、哪条工具结果）；
- **写入要被反思**：定期清理过时记忆，避免知识库污染；
- **读取要被评估**：检索结果是否被 Agent 实际使用？是否有"检索但不引用"的浪费？

### 5.5 Mem0：抽取-更新式记忆层

**Mem0** 把记忆管理显式化为两个 LLM 阶段：先从对话中**抽取**候选事实，再对记忆库做**更新决策**——ADD（新事实）、UPDATE（与旧记忆冲突或细化）、DELETE（过时）、NOOP（不值得记）。相比把整段对话原文入库，它维护的是一个去重、增量更新的小型事实库，并以 API/中间件形式嵌入任意 Agent 框架。

### 5.6 记忆全生命周期：写入 → 检索 → 反思 → 巩固 → 遗忘

```text
对话/工具结果 ──写入──▶ 记忆库（情景 / 语义 / 程序性）
                        │   ▲
                   检索 │   │ 巩固（合并、去重、蒸馏）
                        ▼   │
                   当前 prompt ◀── 反思（生成高层洞察）
                        │
                  遗忘（容量淘汰、过时清理）
```

- **写入**：决定"什么值得记"（5.3 的触发策略），并附上出处（哪轮对话、哪个工具结果）保证可追溯；写入前做语义去重——与既有记忆相似度超过阈值就合并而非新建；
- **检索**：多路召回（语义 + 时间 + 实体）再 rerank，打分常用加权形式：

$$\text{score}(m) = \alpha \cdot \text{sim}(q, m) + \beta \cdot \text{recency}(m) + \gamma \cdot \text{importance}(m)$$

  这是 Generative Agents 记忆流检索的经典设计；
- **反思**：定期对记忆库提"高层问题"（用户的长期目标是什么？哪些偏好反复出现？），生成新的洞察条目——反思产出的是语义记忆而非情景流水账；
- **巩固**：合并同义条目、用新事实更新旧事实、把长对话压缩为摘要，必要时蒸馏进系统 prompt（对应 CLS 的"慢巩固"）；
- **遗忘**：容量控制与清理。可按重要性 × 新近度淘汰；MemoryBank 进一步用艾宾浩斯遗忘曲线给记忆强度建模 $R(t) = \exp(-t/S)$，其中 $S$ 随复习次数增大——"常被用到的记忆更不容易忘"。

### 5.7 代表性方案对比

| 方案 | 记忆组织 | 写入方式 | 检索方式 | 适用场景 |
|---|---|---|---|---|
| MemGPT / Letta | 主存（上下文）+ 外存分页 | LLM 自主 recall/archive | LLM 决定换页 | 单 Agent 长对话、有状态 Agent 服务 |
| Mem0 | 扁平事实库（+ 图可选） | 抽取 + ADD/UPDATE/DELETE 决策 | 向量 + 图混合 | 嵌入现有 Agent 的记忆中间件 |
| A-MEM | 结构化笔记 + 笔记间链接 | 每轮生成笔记并自动建链 | 向量 + 链接遍历 | 需要可演化、可解释记忆的个人助理 |
| Mirix | 多层（核心/事件/知识/工具/反思） | 每层独立策略 | 每层独立检索 | 多类型信息混合的长期运行 Agent |
| GraphRAG / Zep 式 | 时序知识图谱 | 实体关系抽取 | 多跳图查询 | 事实密集、需要多跳推理的领域 |

## 6 实践建议 {#6}

1. **明确记忆目标**：要解决"短期上下文溢出"还是"跨会话个性化"？两者策略不同。
2. **混合形态**：向量 + 摘要 + 实体，不要押注单一形态。
3. **写入策略可配置**：对个人偏好用事件触发，对工作汇报用批量摘要。
4. **检索要可控**：检索返回 top-k + 重要性打分；不是所有的相关记忆都该注入。
5. **反思与遗忘**：长期记忆库需要"清理"——过期、不重要、错误的记忆要被淘汰。
6. **评测记忆系统**：用 MemRecall、LoCoMo 等基准测检索准确率与答案一致性。
7. **隐私边界**：长期记忆涉及用户数据，需做权限分级与脱敏。

### 6.1 评测基准

- **LoCoMo**：超长多会话对话（数百轮、跨天/跨月），考察跨会话事实召回、时间推理与知识更新，是最常用的对话记忆基准；
- **LongMemEval**：围绕五类能力出题——信息抽取、多会话推理、时间推理、知识更新、拒答（记不住就应承认不知道），比单纯 QA 更能暴露"过时记忆"问题；
- **MemoryBench / MemRecall 类**：偏工程口径，考察写入-检索管道的 recall@k、答案一致性与延迟/成本开销。

通用教训：基准高分不等于线上体验好——还需在自己的真实会话分布上做影子评测；同时注意测试集污染（基准对话可能已进入预训练语料）。

### 6.2 何时写入、检索策略与容量控制

- **何时写入**：默认"事件触发 + 会话结束摘要"双通道，纯每轮写入几乎必然冗余；
- **检索策略**：top-k（k 取 5–20）+ rerank；时间敏感的问题交给时间加权；注入时带时间戳与出处，避免把过时记忆当现行事实；
- **容量控制**：给每轮 prompt 设记忆 token 预算；记忆库分层（热 = 最近 N 天原文，冷 = 归档摘要）；定期跑巩固任务合并旧记忆；给临时任务状态这类"可遗忘"信息设 TTL。
